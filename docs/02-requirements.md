# 02. 요구사항 정의

> 2026-11-03 Node 구현 기준으로 갱신 (docs/18 P0-9). §1 가정·§2 흐름·FR-P1·FR-R1·FR-S3/S4·§4 일부·§5만 고쳤고 나머지 절은 원문 그대로다.

## 0. 제품 한 줄
카카오톡 대화 내보내기 파일을 올리면, AI 페르소나 **「까비서」(가제, 설정으로 변경)** 가 대화를 전부 읽고 **솔직하고 웃기지만 근거 있는 보고서**를 써준다. 1:1(연인·썸·친구)과 단톡방 모두 지원. 판정 문장은 스크린샷해서 단톡방에 던질 수 있게 설계한다.

## 2. 사용자 흐름 (MVP, 구현 기준 — 위저드 모델, 09 §6)
1. 랜딩(`/`): 서비스 설명 + 가상 샘플 카드 + 신뢰 3칸 + "내보내기 방법" 가이드(`/guide/export`: Android / iPhone / 휴대폰에서 바로 올리기 / PC).
2. 설정 위저드 `/setup` **7단계**: ① 대화 유형(연애 / 친구 단톡방 / 친구 한 명 / 가족 / 회사·팀 / 기타) → ② 앱(카카오톡만 활성) → ③ 업로드(txt/csv/zip 드롭존 → 즉시 파싱 → 메시지 수·📶 신호 등급 카드, "눌러서 대화 바꾸기", "🛡 올린 데이터는 비공개로 지켜져요" 시트) → ④ 참여자 확인(대화방 이름, 메시지 비율 막대, **봇 기본 제외**(해제 가능), 제외 체크, "이게 나예요"(선택), 프로필 합치기·병합 제안) → ⑤ 이름 정리 → ⑥ 보고서 언어(한국어만) → ⑦ 보고서 만들기(톤 반말/존댓말, 질문 1개 ≤300자).
3. 생성 직후 통계 스토리 `/c/{id}/story` 7장(Tier 0, LLM 없음, 즉시)을 넘기며 기다린다 → 마지막 장에서 보고서 페이지로.
4. 생성 대기(`/c/{id}/reports/{seq}`): 진행 바 + 단계 문구(줄 서 있어요 → 대화를 펼치고 → 읽고 있어요 i/n → 생각을 정리 → 근거 대조). 소요 카피는 **"보통 2~5분, 긴 대화는 최대 10분"**(ETA = 메시지 수 기준 2~10분, 09 §5). 페이지를 떠나도 링크(+쿠키)로 복귀 가능. 완료 메일은 미결(§5).
5. 보고서 열람: 보고서 제목(조어) → 결론 보고(판정) → 재밌게 읽은 장면(5~7) → **멤버 페르소나(전원, 메인 코너: 주제·유형·칭호·2~3문단 로스트 + 실제 메시지 말풍선 + 한 줄 결론)** → 진짜 역학 → 변동 보고·바뀐 주 → 누가 먼저 치고 누가 아닌 척하는지 → 둘(방)만의 언어와 반복되는 농담 → 발견 → 비서 제안 3건·내가 너라면 → 이달의 상 → 점수(설정) → 숫자로 보는 우리 → (질문 답) → 공유 카드 → 면책·품질(07 §2, 09 §3). 화법은 14 문서.
6. 공유: 비공개 공유 링크 켜기/끄기(재발급 시 구 링크 무효), 공유 페이지 `noindex`, OG 이미지 = 공유 카드 PNG.
7. 삭제: 대화 전체(원문·통계·보고서·공유 링크) 삭제 **또는 보고서 하나만 삭제**. 즉시, 복구 불가.
8. 재생성: 대시보드 `/c/{id}` 새 보고서 폼 또는 보고서 페이지 "새 보고서"(`/setup?c=`로 참여자·이름 재정리 후) — 같은 대화로 다른 유형·톤·질문의 보고서 N번(소유자당 일 10건).

## 3. 기능 요구사항 (FR)

### 3.1 업로드·파싱
- FR-U1 txt/csv/zip 업로드, 다중 txt(분할) 병합. 한도·에러 코드는 03 §1.1·§6.
- FR-U2 포맷 자동 감지(Android/iOS/PC/CSV/영문), 멀티라인·시스템·미디어 분류, 인코딩 폴백.
- FR-U3 업로드 직후 동기 파싱(<20초/50MB). 결과: 참여자 목록·메시지 수·기간·경고.
- FR-U4 동일 파일(sha256) 재업로드 시 같은 소유자면 기존 대화 재사용(멱등), 다른 소유자면 신규.
- FR-U5 원문은 AES-256-GCM 암호화 저장. 파싱된 메시지 전문은 DB에 저장하지 않고 필요 시 원문을 복호화해 재파싱(결정적 파서).

### 3.2 참여자
- FR-P1 업로더("나") 지정은 **모든 유형에서 선택 사항**(nullable — 원 서비스 위저드도 묻지 않음, 17·18 P0-4). 지정하면 전사에 `(나)` 표식, 2인 대화의 `stats.balance`(업로더 기준 비대칭 지표), 프롬프트의 "업로더도 봐주지 않되 자기 인식이 되게" 지침이 켜진다. 미지정이면 `(나)` 표식 없음, 2인 대화의 `balance`는 첫 참여자를 기준으로 계산(숫자 사실·Tier 0가 이름으로 표기하므로 결과는 대칭 — `computeBalance` 폴백, ADR-16), 프롬프트에 "내가 너라면은 이 보고서를 읽는 사람에게, 한쪽 편 들지 않기" 지침. `UPLOADER_NOT_SELECTED` 오류 코드는 없다.
- FR-P2 이름 변경 병합(수동 + 1:1 자동 제안), 제외, 표시 이름 변경. 변경은 이후 생성되는 보고서에만 적용.
- FR-P3 참여자 2명 미만(제외 후) → 409 `NOT_ENOUGH_PARTICIPANTS`.

### 3.3 보고서 생성
- FR-R1 대화 유형(`focus`) `AUTO | ROMANCE | FRIENDS_GROUP | FRIEND_ONE | FAMILY | WORK | OTHER`(위저드 1단계 카드 6종 + 미선택 `AUTO`; 대시보드 새 보고서 폼은 7칩), 톤 `CASUAL | POLITE`, 질문(선택, ≤300자). 유형별 프롬프트 지침(`FOCUS_GUIDE`, 07 §5)이 청크·종합 단계에 들어가고 "업로더가 고른 유형과 실제 대화가 다르면 판정 첫 문단에서 한 줄로 짚고 실제에 맞춰 쓴다". 점수 세트는 `WORK`→WORK, 그 외는 참여자 수로 2인 PAIR / 3인+ GROUP(07 §3.1). `resolvedFocus`는 `AUTO`일 때만 해석(3인+ → `FRIENDS_GROUP`, 2인은 LLM 관계 유형 코드로 `ROMANCE`/`FRIEND_ONE`), 아니면 선택값 그대로.
- FR-R2 비동기 생성. 대화 1건당 동시 실행 보고서 1개(409 `REPORT_ALREADY_RUNNING`). 소유자당 일일 상한(기본 10).
- FR-R3 상태 머신 `QUEUED → RUNNING → SUCCEEDED | FAILED | CANCELED`. 취소는 QUEUED/RUNNING에서만. 실패 시 재시도(`/retry`)는 FAILED에서만, 시도 3회 상한.
- FR-R4 생성 결과는 **스키마 버전이 붙은 JSON**(07). 렌더는 JSON 기반.
- FR-R5 모든 근거 인용은 메시지 ID로 접지되어야 하며, 서버가 존재·화자 일치를 검증한다. 미접지 근거는 제거, 근거 0개 발견은 신뢰도 "낮음"으로 강등하거나 제거(규칙은 07).
- FR-R6 보고서에 커버리지(LLM이 실제 읽은 메시지 비율), 접지 통계, 사용 모델, 생성 시각을 기록(품질 섹션, 사용자에게는 커버리지만 노출).
- FR-R7 출력 언어 검증: 한국어·영문 외 문자(한자·가나) 포함 시 1회 재생성, 재실패 시 해당 필드 제거.
- FR-R8 안전 규칙: 보호 속성·외모·정신건강 진단 금지, 자해·폭력·학대 신호 감지 시 톤 완화 + 안내 문구(07 §6).

### 3.4 열람·공유·삭제
- FR-S1 소유자만 대화/보고서 열람(소유자 토큰). 공유 링크는 보고서 단위 토큰, 활성/철회 가능, 공유 페이지는 통계 요약·판정·점수·발견·순간을 보여주되 **원문 전체는 노출하지 않음**(인용 카드만).
- FR-S2 공유 카드(판정 헤드라인 + 점수 요약) 레이아웃은 모바일 스크린샷 비율(9:16 안에 들어오는 세로 카드).
- FR-S3 대화 삭제 시 원문·통계·참여자·보고서·공유 토큰 **모두 하드 삭제**(활성 보고서는 먼저 취소), LLM 호출 로그는 `report_id`만 NULL로 남김(숫자만). **보고서 단위 삭제**(`DELETE /api/v1/reports/{id}`, 생성 중이면 409 `INVALID_STATE` → 먼저 취소)도 제공하며 보고서 페이지에 "이 보고서 삭제" 버튼이 있다.
- FR-S4 원문 자동 삭제: `expires_at`(업로드 + `RAW_RETENTION_DAYS` 7일, 보고서 생성에 따른 연장 없음) 경과 시 원문만 삭제(보고서는 유지, 새 보고서·재시도는 409 `RAW_EXPIRED`). 보존 기간은 대시보드 헤더("원문은 YYYY-MM-DD에 자동 삭제돼요")·`/privacy`·드롭존 신뢰 시트에 고지한다.

### 3.5 운영
- FR-O1 LLM 호출마다 토큰·비용·지연·모델·결과를 로그 테이블에 기록(본문 없음).
- FR-O2 보고서별 비용 상한(토큰) 초과 예상 시 샘플링으로 축소하고 커버리지에 반영; 절대 상한 초과 시 `COST_LIMIT_EXCEEDED` 실패.
- FR-O3 메트릭: 업로드 수, 파싱 실패율(코드별), 보고서 성공률, 평균 생성 시간, 토큰/비용 합계, 접지 제거율.

## 5. 범위 밖 · 미결 (구현되지 않은 것)
- **미결(사용자 결정 대기, docs/18 P0-1 · 13 ADR-08)**: 이메일 6자리 인증 코드, 완료/실패 메일, 재인증으로 "내 보고서" 복귀. 현재 신원·전달·복귀 수단은 쿠키 `gg_owner` + 링크만.
- 미구현(백로그, docs/18 §12): 보고서 체인(`parent_report_id`, "하나 더 묻기")·슬라이딩 원문 만료(P1-1), 이메일 인바운드 업로드(P1-3), `/faq`·`/support`(P1-6), 유형별 SEO 랜딩(P1-11), 결제·미리보기 게이팅(`visibility` 플래그만, P2-1), 다국어 UI·영어 리포트(P2-2), Personal read(P2-3), 두 번째 페르소나(P2-4), WhatsApp/LINE 파서(P2-5), 사용자 간 "친구 패스", 이름 가명 처리 옵션(13 ADR-13).
- 이전 "v2"였으나 구현됨: 공유 카드 PNG(`next/og`, `/r/{token}/card.png`)와 OG 이미지.

## 6. 수용 기준 (MVP Done)
1. 03 §7 픽스처 전부 골든 테스트 통과.
2. 샘플 가상 대화 3종(1:1 균형, 1:1 일방, 단톡 8명)으로 보고서 생성 성공, 미접지 인용 0건 노출, 한자/가나 0건, 모든 필수 섹션 존재.
3. 워커 강제 종료 후 재기동 시 RUNNING 보고서가 3분 내 재개·완료(체크포인트 재사용으로 LLM 재호출 최소화).
4. 삭제 후 DB에 원문·보고서·토큰 잔존 0건.
5. 공유 링크 철회 후 404.
6. 모든 에러 응답이 `{code, message, fieldErrors[]}` 형식.
