# 09. 프론트엔드 · UX

## 1. 원칙
모바일 우선(카톡은 폰에서 내보낸다), 한 화면에 한 가지 행동, 보고서는 **스크린샷을 찍고 싶게**, 공유 페이지는 원문을 흘리지 않게. 서버 렌더(Thymeleaf) + HTMX(부분 갱신) + Alpine(토글) + Tailwind. 다크 모드 지원(`prefers-color-scheme` + 토글).

## 2. 화면 목록
| 경로 | 목적 | 핵심 요소 |
|---|---|---|
| `/` 랜딩 | 15초 안에 이해·업로드 | 히어로("카톡 올리면 까비서가 다 읽고 솔직하게 말해줌"), 3단계 안내, 가상 샘플 보고서 카드 3장(판정·점수·인물평), 프라이버시 3줄(암호화·7일 삭제·학습 미사용), CTA |

| `/r/{token}` | 공유 보고서 | 소유자 전용 요소 제거(삭제·재생성·원문 통계 세부), 상단 "까비서 보고서 · 공유됨", 하단 "내 카톡도 분석하기" CTA, noindex |
| `/privacy`, `/terms` | 고지 | 보존 기간·AI 처리 위탁·면책 |

## 3. 보고서 레이아웃 (완료 상태)
세로 스크롤 1열, 최대 폭 680px, 카드 간격 24px, 16px 좌우 거터.
순서는 07 §2(공식 뼈대 중심)와 동일하다.
1. **헤더 카드**: 제목, 기간·메시지 수, 참여자 칩(업로더 "나" 표식), 커버리지 뱃지("까비서가 100% 읽었어요"/"62% 발췌"), "오늘 까비서 기분: 직진" 칩, 면책 한 줄.
2. **판정 카드(히어로)**: 큰 헤드라인(28~32px, 2줄 이내), 관계 유형 라벨 칩, 본문 3~4문단(반전 문단의 메시지 ID는 인라인 말풍선으로 펼침). 우상단 "공유 카드 보기".
3. **진짜 역학**: 본문 2~3문단. 단톡방이면 역할 3칩(판을 들고 있는 사람 / 사라지는 사람 / 판을 쥔 사람) + 참여자 아바타.
4. **바뀐 주**: 주차 라벨 크게("2025년 6월 둘째 주"), 전/후 2열 수치 비교, 결정적 한 줄 말풍선(이름·시각·본문).
5. **인물별 의견**: 참여자당 카드 — 별명(큼), 역할, 선언문 1개, 어워드 리본, 뱃지(아이콘+이름, 탭하면 근거), 소프트 랜딩(옅은 색), 근거 말풍선 접기. 단톡 13명+는 `others` 요약 카드.
6. **발견**(4~6): 「보인 것 / 내 해석 / 확신」 3행 카드 + 근거 말풍선(최대 3). 각 카드 "이 발견 공유".
7. **내가 너라면**: 체크 아이콘 카드 3장, 시한 칩("이번 주").
8. **어워드**: 트로피 카드 3~6개(상 이름·수상자·사유·근거). 가로 스크롤.
9. **점수**(설정 on 시): 2열(모바일 1열) 미니 카드 — 라벨, 큰 숫자 `3.2/5`, 게이지 바, 한 줄, confidence 칩(확실해/아마도/감이야).
10. **검증된 순간**: 가로 스크롤 카드(kind 아이콘: 😂 💓 🥹 🏓 😶 ⚡), 말풍선 1~3개 + 캡션. "실제 대화 그대로" 라벨.
11. **숫자로 보는 우리**: 월별 메시지 막대(인물별 색), 시간대 히트맵(요일×시간), 답장 속도 비교(중앙값·p90), 선톡 비율 도넛, 미디어 비율. 각 차트 아래 까비서 캡션. **MVP는 서버 SVG**(의존성 0, 스크린샷 안정).
12. **까비서의 답**(질문 있을 때).
13. **공유 카드 미리보기**: 1080×1920 비율 세로 카드(§4), 서명 멘트 포함. "이미지로 저장"(v2: 서버 PNG) / MVP는 "이 영역을 캡처" 가이드 + 공유 링크 생성 버튼.
14. 푸터: 삭제·재생성·면책·문의.

## 4. 공유 카드 스펙
- 비율 9:16 안쪽, 안전 영역 상하 12%. 배경 그라디언트(톤별 2종), 상단 "까비서의 판정", 중앙 헤드라인(최대 2줄, 자동 폰트 축소), 하단 점수 2개 요약 + 서비스명·URL 워터마크.
- 텍스트 길이 제한: headline ≤40자, subline ≤30자(LLM 지침 + 서버 절단).
- CSS 단독 렌더(폰트 로컬 포함: Pretendard variable 1종 self-host).

## 5. 진행 상태 카피 (폴링 조각)
| 단계 | 문구 |
|---|---|
| QUEUED | "까비서가 줄 서 있어요. 곧 시작해요" |
| LOAD/STATS/RENDER | "까비서가 대화를 펼치고 있어요 · 17,110개 메시지" |
| CHUNK i/n | "까비서가 {월} 대화를 읽고 있어요 ({i}/{n})" |
| SYNTH | "까비서가 생각을 정리하고 있어요. 보통 1~2분" |
| VALIDATE | "근거를 대조하고 있어요" |
| FAILED | 코드별: `LLM_UNAVAILABLE` "까비서가 잠깐 자리를 비웠어요. 다시 시도해 주세요" / `COST_LIMIT_EXCEEDED` "대화가 너무 길어서 이번엔 못 읽었어요. 기간을 나눠 올려주세요" / `LLM_REFUSED` "이 대화는 까비서가 분석하지 않기로 했어요" |
페이지를 떠나도 되며 링크로 돌아오면 이어 보인다(쿠키 필요) — 안내 문구 포함.

## 6. 참여자 확인 UX 디테일
- 1:1에 이름이 3개 이상이면 병합 제안을 **기본 체크 해제**로 표시(오탐 방지), 확인 전 "같은 사람인가요?" 미리보기(두 이름의 활동 기간 바).
- 업로더 미선택 상태에서 "보고서 만들기" 비활성 + 이유 툴팁.
- 단톡방 30명+: 검색 필터, "메시지 10개 미만 자동 제외" 토글(기본 ON, 보고서엔 `others`로 요약).

## 7. 접근성·성능
- 색 대비 AA, 포커스 링, 차트에 `aria-label` 수치 요약, 이미지 대체 텍스트.
- 보고서 페이지는 JS 없이도 읽힌다(HTMX는 진행 상태에만).
- Tailwind 빌드 산출 CSS ≤ 60KB, 폰트 1종 서브셋, 외부 CDN 의존 0(공유 페이지 신뢰성).
